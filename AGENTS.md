# AGENTS.md — @meddleware/ui

Shared Vue 3 component library for the `@meddleware` UIs. Delivers the layout shell (AppHeader, AppSidebar, AppFooter), colour-mode control, and UI primitives. Built on `@meddleware/design-tokens`.

## Package structure

```text
src/
  components/     Vue SFCs — all public components
  composables/    TypeScript composables (useColorMode)
  internal/       Internal helpers not exported to consumers (panel.ts)
  styles/         base.css — element defaults AND every component's scoped styles (consumers need it)
  index.ts        Public API — all exports
  env.d.ts        Vue SFC type declaration shim
dist/             Compiled output (generated by `npm run build`) — what npm consumers receive
  ui.js           ESM bundle
  index.d.ts      TypeScript declarations
  base.css        Compiled CSS
```

There IS a build step. The package ships `dist/` to npm consumers. Run `npm run build` before publishing.

## Adding a component

1. Create `src/components/MyComponent.vue` using design token CSS vars (`var(--bg)`, `var(--accent)`, etc.) and `--mw-panel-*` tokens for variant-aware panels.
2. Export it from `src/index.ts`.
3. Run `npm run build` to verify it compiles cleanly.
4. Add a row to the exports table in `README.md`.

## Theming

- Components use semantic tokens (`--bg`, `--surface`, `--text`, etc.) for theme-aware styling.
- Layout shell components (`AppHeader`, `AppSidebar`, `AppFooter`) accept a `variant: 'light' | 'dark' | 'transparent'` prop and use the theme-independent `--mw-panel-{dark,light}-*` tokens so a dark header renders correctly on a light page.
- `useColorMode` manages the `data-theme` attribute on `<html>` and persists to `localStorage`. It is a module singleton — import it anywhere; all callers share the same state.
- `ColorModeControl` is a presentational component only — it does not own state. Bind it with `v-model` to `useColorMode`.

## Peer dependency

`vue ^3.5.0` is a peer dependency — not bundled. Consumers provide their own Vue instance.

`@meddleware/design-tokens` is a direct dependency. Consumers must still import the tokens CSS once at their app entry:

```ts
import '@meddleware/design-tokens/tokens.css'
import '@meddleware/ui/base.css'  // required: element defaults + the components' scoped styles
```

## Build

```sh
npm install
npm run build   # vue-tsc type-check + vite lib build → dist/
```

The build uses Vite in library mode. Output is a single ESM bundle (`dist/ui.js`) plus declarations and CSS.

## Publishing

Published to npmjs only on `v*` git tags via `.github/workflows/npm-publish.yml` using OIDC trusted publishing — no long-lived secrets required.

**JSR is not used for this package.** JSR uses Deno under the hood and does not support Vue SFCs (`.vue` files). The entire component surface of this package depends on Vue SFCs, so there is nothing meaningful to export to JSR.

To release: bump `version` in `package.json`, add a CHANGELOG entry, run `npm run build` to verify, commit, tag (`git tag v0.x.y`), push the tag.

## What to avoid

- Do not add business logic or state beyond what a reusable component library needs.
- Do not bundle Vue — it is a peer dependency.
- Do not publish without running `npm run build` first — the `dist/` directory is what consumers receive.
- Do not use hardcoded hex colours in component styles — always reference CSS custom properties from `@meddleware/design-tokens`.
