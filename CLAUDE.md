# CLAUDE.md — @meddleware/ui

Shared Vue 3 component library for the `@meddleware` UIs. Delivers the layout shell (AppHeader, AppSidebar, AppFooter), colour-mode control, and UI primitives. Built on `@meddleware/design-tokens`.

## Package structure

```text
src/
  components/     Vue SFCs — all public components
  composables/    TypeScript composables (useColorMode, useSeason, useNow, useStatusSnapshot, usePager)
  internal/       Internal helpers not exported to consumers (panel.ts)
  styles/         reset.css — element defaults and utilities (global, `@layer mw.reset`); components carry their own scoped CSS
  theme-init.js   Plain pre-paint script (saved colour mode + season); published verbatim
  index.ts        Public API — all exports
  env.d.ts        Vue SFC type declaration shim
vite/             Build plugin (css-delivery.ts) — not published
dist/             Compiled output (generated by `npm run build`) — what npm consumers receive
  index.js        ESM entry; one module per source file (`components/UiButton.js` …) so a bundler keeps only what is used
  components/*.css  Each component's CSS, imported by its own module (tree-shaken with it)
  reset.css       The global reset; base.css = reset + every component (the old single-file entry)
  theme-init.js   The pre-paint script
  index.d.ts      TypeScript declarations (and one .d.ts per module)
```

There IS a build step. The package ships `dist/` to npm consumers. Run `npm run build` before publishing.

## Adding a component

1. Create `src/components/MyComponent.vue` using design token CSS vars (`var(--bg)`, `var(--accent)`, etc.). Its scoped `<style>` is its own CSS: the build wraps it in `@layer mw.components` (postcss.config.js) and imports it from the component's module. Panel-aware components use the `mw-panel--<variant>` classes from the reset.
2. Export it from `src/index.ts`.
3. Add it to `gallery/ComponentGallery.vue` (the browser contrast gate audits it in all 10 theme × season looks, at AA **and AAA**), a behaviour test in `src/__tests__/components.test.ts` and an axe case in `a11y-primitives.test.ts`.
4. Run `npm run build` to verify it compiles cleanly and `npm run lint` (css, js and html).
5. Add a row to the exports table in `README.md`.

## Contrast: AAA is the bar

The gallery e2e fails on any WCAG AA **or AAA** violation (`color-contrast-enhanced`, 7:1) in every look. The tokens guarantee 7:1 for text and label roles on the canvases, but the tokens cannot see two things a component can get wrong:

- **Tinted backgrounds.** Text drawn in a tone colour over a tint of that tone (`color-mix`) loses contrast. Keep the text in `--text` and let the border and the tint carry the tone (UiNotice, UiBadge).
- **`opacity` on text.** It silently takes the label below the floor. Use `--muted` (which is AAA) or `--text`, never `opacity`, to dim text. A disabled control is exempt from contrast, so `filter: grayscale()` is how it is dimmed.
- **A control identified by its edge.** A text field, textarea or select is found by its border, so that border must reach 3:1 (WCAG 1.4.11): use `--control-border`, never `--border` (a divider, 1.3–1.4:1). A button is identified by its label and keeps `--border`. axe cannot see this; `field-boundary.test.ts` and the token contrast gate hold it.
- **Browser defaults.** A bare `<button>` in a dark theme gets the browser's grey (5.3:1); the reset gives it a token-based base style.
- **Forced colours (Windows High Contrast)** drop backgrounds and shadows. A state drawn with a background alone (the chosen colour mode, the current sidebar item) needs an edge of its own in `@media (forced-colors: active)`; `e2e/forced-colors.spec.ts` checks it.
- **Hover must not change a fill under a label.** UiButton's hover is an inner ring in the label colour, not a `filter`.

## CopyrightLine component

`CopyrightLine` is a reusable copyright statement component. It renders a symbol link (copyright, copyleft, or kopimi) followed by a year and organisation name, plus an optional rights statement.

### Legal files

The `legal/` directory (repository only — NOT in the npm package) holds the legal documents linked by CopyrightLine:

- `copyright.html` — Standard copyright notice
- `copyleft.html` — Copyleft legal notice
- `powr.broccoli-kopimi.pdf` — Kopimi legal notice

**For consuming apps:** by default the component links to the one canonical host, `https://meddleware.co.uk/legal/` (`legalBase`), so an app ships no copies. An app that must serve them itself passes `legal-base="/legal/"` and copies the files from this repository's `legal/` directory into its `public/legal/`. The PDF is third-party artwork whose source was not recorded when it was added; its SHA-256 is `6887d78b0eab1fe24d02cc712c08a445aaa1e00f318b467b640a53d60ce51480` (see `legal/README.md`).

### Usage

```vue
<CopyrightLine
  symbolVariant="kopimi"
  organisation-name="Meddleware"
  rightsStatement="jam"
/>
```

### Props

- `organisationName` (string, required) — Organisation name to display
- `year` (number, optional) — Year to display; defaults to current year
- `rightsStatement` (string, optional) — Rights statement: `'all'` (default), `'none'`, `'jam'`, or a custom string
- `symbolVariant` (string, optional) — Symbol type: `'copyright'` (default), `'copyleft'`, or `'kopimi'`
- `legalBase` (string, optional) — Where the documents are served; default `https://meddleware.co.uk/legal/` (a root-relative path serves them from the app's own origin)
- `symbolHref` (string, optional) — Override the legal document link
- `symbolLabel` (string, optional) — Override the link aria-label

## Sidebar navigation components

Two companion components build accessible hierarchical sidebar navigation.

### `SidebarItem`

Presentational entry button: label + optional emoji icon, active and disabled states.
The host owns selection state and must pass `:active` and `@click`. Use with
`<router-link custom v-slot="{ navigate }">` for router-driven navigation.

**Props:** `label` (string, required), `icon` (string, optional emoji),
`active` (boolean, default `false`), `disabled` (boolean, default `false`).

### `SidebarGroup`

Wraps related `SidebarItem`s under a visible section header using native semantics: a
`<fieldset>` (implicit `group` role) whose visible `<legend>` is the group's accessible
name — announced once, with no ARIA attributes or hidden duplicate label.

**Props:** `label` (string, required), `level` (`1 | 2`, default `1`).

Two visual levels:

- `level="1"` — top-level category (e.g. "Blockchain"): uppercase, `--tracking-wide`,
  75 % opacity. Adds `--space-2xs` top gap when preceded by a sibling group.
- `level="2"` — sub-group within a category (e.g. "Sui"): normal case, 60 % opacity,
  indented label; items gain `--space-3xs` left padding.

**Pattern — two-tier sidebar hierarchy:**

```vue
<SidebarGroup label="Blockchain" :level="1">
  <SidebarGroup label="Sui" :level="2">
    <router-link to="/dao" custom v-slot="{ navigate }">
      <SidebarItem label="DAO" icon="🏛" :active="isDao" @click="navigate" />
    </router-link>
    <!-- … more items … -->
  </SidebarGroup>
</SidebarGroup>
```

**Accessibility output (abbreviated):**
> "Blockchain, group; Sui, group; DAO, button, current page"

**Scaling:** add more `<SidebarGroup label="Ethereum" :level="2">` blocks (or a new
`level="1"` group for a different top-level category) as new chains are added. No
changes to existing items or groups are required.

## Markup conventions (semantic HTML)

- Prefer the semantic element over a `div`: `<dl>` for key/value (UiStatGrid), `<fieldset>`/`<legend>` for named groups (ColorModeControl, UiSegmentedControl,
  SidebarGroup), `<section>` + heading for titled surfaces (UiPanel, UiCard), `<small>`/`<time>`
  for secondary metadata. A `div` is used only where no element fits and a box is required
  (`UiDataTable`'s scroll container, `AppTabNav`'s `role="tablist"`, `UiToolbar`'s `role="toolbar"`).
- Layout-shell slots render **directly** (no wrapper elements); consumers style their own slot
  content. Only component-owned content is grouped (e.g. AppFooter's documentation `<nav>`).
- Per-instance style values go through SFC `v-bind()` in the `<style>` block (routed via a local custom property such as `--_width`), never a `:style` attribute in the template. A panel's `colors` overrides (AppHeader/AppSidebar/AppFooter) are written with `usePanelOverrides` (CSSOM `style.setProperty`), so nothing inline is rendered and a strict `style-src` is enough.
- **Native elements, wrapper-free roots.** A component with a native single root (UiInput, UiSelect, UiButton) lets attributes fall through to it; do not start a template with a comment (in development it makes the root a fragment). Inside a list item, `<header>`/`<footer>` become page landmarks, so use plain elements there (UiCard `as="li"`).
- **URL bindings call the helper in the template** (`:href="safeHref(href)"`): the fleet lint rule does not follow a computed. `<output>` and `role="status"` regions are always mounted (UiLiveStatus, UiCopyButton); a `v-if` on the region breaks announcements.
- **Never put a `<tr>` in `UiDataTable`'s `head` slot.** The component owns the row; a dev check warns.
- Dialogs use `UiDialog` (native `<dialog>` › `<article>` › `<header>`/`<footer>`); dismissal uses
  the native `closedby` attribute plus a script-attached backdrop fallback, so no interactive
  handler sits on the non-interactive `<dialog>`.
- `npm run lint:html` (html-validate + html-validate-vue) checks template nesting/content models;
  `src/__tests__/a11y.test.ts` mounts every component in jsdom and runs axe (structure and ARIA only: jsdom has no layout, so the colour-contrast rule cannot run there). Colour is checked in a real browser: `npm run test:e2e` (Playwright + axe over `gallery/`, every theme × season, plus the modal dialog and the non-default shell panels). Add a new component to `gallery/ComponentGallery.vue` as well. Keep all three green when adding one.

## Theming

- Components use **colour-agnostic role tokens** (`--bg`, `--surface`, `--text`, `--accent`,
  `--warning`, `--ok`, `--danger`, `--info`, `--highlight`, `--focus-ring`, …) and the
  **sacred-geometry scales** (`--space-*`, `--font-size-*`, `--leading-*`, `--tracking-*`,
  `--radius`) from `@meddleware/design-tokens`. Never hardcode rems/hexes or reference colour-named
  ramps (`--mw-gold-*`, `--mw-oxblood-*`) — those are retained swatches, not for components. The one
  allowed literal is a sub-scale hairline (e.g. 2px) where the Fibonacci floor (0.25rem) is too big;
  comment it.
- Focus uses `--focus-ring` (a distinct blue), not `--accent`, so focus never reads as an error.
  Transitions use `--transition-base`. Hover states are subtle shifts (a tint, a ring), never `opacity` on text.
- `reset.css` ships utilities (components assume them): `.mw-noise` (SVG-noise layer), `.mw-spinner` (sigil loader),
  `.mw-hand-drawn` (empty placeholder hook for later bespoke SVG/canvas), `.mw-mono`,
  `.mw-visually-hidden` (assistive-technology-only text). All respect `prefers-reduced-motion`.
- Seasonal theming lives entirely in design-tokens (`seasons.css` + `data-season`); components pick
  it up automatically via the role tokens — no per-component seasonal code.
- Layout shell components (`AppHeader`, `AppSidebar`, `AppFooter`) accept a `variant: 'light' | 'dark' | 'transparent'` prop and use the theme-independent `--mw-panel-{dark,light}-*` tokens so a dark header renders correctly on a light page.
- `useColorMode` manages the `data-theme` attribute on `<html>` and persists to `localStorage`. It is a module singleton — import it anywhere; all callers share the same state.
- `ColorModeControl` is a presentational component only — it does not own state. Bind it with `v-model` to `useColorMode`.

## Peer dependency

`vue ^3.5.0` is a peer dependency — not bundled. Consumers provide their own Vue instance.

`@meddleware/design-tokens` is a direct dependency. Consumers must still import the tokens CSS once at their app entry:

```ts
import '@meddleware/design-tokens/tokens.css'
import '@meddleware/ui/reset.css'  // required once: element defaults, focus ring and utilities (components bring their own CSS)
```

## Build

```sh
npm install
npm run build   # vue-tsc type-check + vite lib build → dist/
```

The build uses Vite in library mode with `preserveModules`: one JS module per source file, each component importing its own CSS. `vite/css-delivery.ts` names the CSS after the component (Rolldown does not let a plugin rename files through the bundle object, so the names are chosen in `assetFileNames`), injects the CSS imports, publishes `theme-init.js` and writes the `base.css` aggregate. `postcss.config.js` autoprefixes and wraps CSS in the cascade layers.

## Publishing

Published to npmjs only on `v*` git tags via `.github/workflows/npm-publish.yml` using OIDC trusted publishing — no long-lived secrets required.

**JSR is not used for this package.** JSR uses Deno under the hood and does not support Vue SFCs (`.vue` files). The entire component surface of this package depends on Vue SFCs, so there is nothing meaningful to export to JSR.

**One-time setup:** configure a trusted publisher on npmjs.com pointing at this repository and `npm-publish.yml`.

To release: bump `version` in `package.json`, add a CHANGELOG entry, run `npm run build` to verify, commit, tag (`git tag v0.x.y`), push the tag.
